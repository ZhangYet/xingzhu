# 行箸 · 古诗词平仄韵脚赏析 App 设计文档

> 暂定名：行箸（取"行于诗卷，箸点平仄"之意）
> 版本：v0.1（设计稿，待评审）
> 日期：2026-08-07

---

## 1. 产品概述

**行箸** 是一款 Android 应用，帮助用户阅读中国古典诗词并理解其**格律**：

- 展示诗词**原文**；
- 按《诗韵新编》标注每个字的**平仄**；
- 按《诗韵新编》将每个**句末字**标注为**韵脚**并给出所属韵部；
- 提供**横排**排版，清晰呈现格律。

### 1.1 目标用户

对古典诗词感兴趣、想学习或赏析格律的普通读者与诗词爱好者（非学术研究者）。产品侧重**直观呈现**，而非严谨的音韵学考据。

### 1.2 核心目标

1. 一个可维护的"已有诗词"收藏书架，支持搜索并添加诗词。
2. 精确且可解释的平仄 / 韵脚标注引擎。
3. 优雅的横排阅读排版。

### 1.3 非目标（v1 不做）

- 不做严谨的中古音 / 上古音考据、多音字全部歧义的穷举判定。
- 不做诗词创作（写诗）、联句、格律自动纠错工具。
- 不做账号、云同步（v1 全部本地存储）。
- 不解析版权受限的注释、译文、赏析文字（仅收录公版原文）。

## 2. 背景概念

| 术语 | 说明 |
| --- | --- |
| 平仄 | 汉字声调在诗词格律中的分类。**平**=平直舒缓，**仄**=曲折低沉。近体诗讲究句中平仄交替、句间平仄相对/相粘。 |
| 《诗韵新编》 | 现代（按普通话读音）编定的韵书，分 **十八韵**（一麻、二波、三歌、四皆、五支、六儿、七齐、八微、九开、十姑、十一鱼、十二侯、十三豪、十四寒、十五痕、十六唐、十七庚、十八东）+ **入声**。其平仄判定依据普通话四声：阴平、阳平 = 平；上声、去声、入声 = 仄。**本 App 的平仄与韵脚统一以此为标准。** |
| 韵脚 | v1 简化为**每个句末字**（按标点切分的"句"的末字），标注其在《诗韵新编》中的韵部，不做押韵归并等额外判断。 |

> **产品设计要点**：平仄与韵脚**统一按《诗韵新编》**标注，同一字在两套体系间不一致的问题（如入声字在普通话中已并入其它声调）在 v1 中不展开处理，避免复杂化。

## 3. 技术选型

| 层面 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Kotlin 2.x + coroutines / Flow | Android 官方首选，协程便于异步加载语料与字典。 |
| UI | Jetpack Compose（BOM），单 Activity + Navigation Compose | 声明式 UI 便于实现自定义排版。 |
| 主题 | Material 3 定制 + 自绘「水墨宣纸」风格 | 见 §7。 |
| 架构 | MVVM + Repository + 单向数据流（StateFlow） | 分层清晰、易测试。 |
| 依赖注入 | Hilt | 官方主流方案。 |
| 本地存储 | Room（KSP） | 书架、诗词、标注结果缓存。 |
| 字典 / 语料 | 随包 assets（JSON/CSV），首次启动解析进内存 | 诗韵新编字典（韵部 + 平仄）为静态数据（数千字，<1MB），无需进 DB，内存查询更快。 |
| 序列化 | kotlinx-serialization | 解析 assets 中的语料与字典。 |
| 模块划分 | `:app`（Android 壳）+ `:engine`（纯 Kotlin 标注引擎，无 Android 依赖） | 引擎可脱离 Android 在 JVM 上做纯单测。 |
| 构建 | Gradle Kotlin DSL + version catalog（`libs.versions.toml`） | 现代标准。 |
| 最低版本 | minSdk 26，targetSdk 35 | 覆盖绝大多数设备。 |

### 3.1 字体

- 内置 **思源宋体 / Noto Serif CJK SC**（开源 OFL 许可）作为诗词正文字体，衬线字形更贴合古籍质感，且对传统字符（〇●、生僻字）支持好。
- 回退到系统 `serif`。
- 平仄标记使用专用记号字，不依赖用户字体。

### 3.2 诗歌数据来源（关键决策）

**v1 方案：内置公开语料库（离线）**

- 从开源项目 [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)（MIT 协议）选取公版文本，**第一版内置 10 首精选名篇**（覆盖五绝、七绝、五律、七律、词等体裁各若干首），打包为 assets 语料。
- 首次启动时导入 Room，作为「已有诗词」书架的初始数据，并作为搜索数据源。
- 新增诗词 = 在语料中**按题目 / 作者检索 → 加入书架**。搜索、结果、加入均为本地操作，离线可用。

**后续（MVP 之后，本期只留接口）**

- 定义 `PoemSource` 接口（`LocalCorpusSource` / 未来的 `RemoteApiSource`），便于接入联网诗词库（如古诗文网类公开接口），获取语料之外的诗词。本期不做，规避接口稳定性与版权风险。

> **开放问题**：用户需求是"搜诗词的题目、作者**新增**古诗词"——v1 以内置语料满足，即"在语料库范围内新增"。若希望覆盖任意诗词，需引入联网数据源，见 §10 开放问题 Q1。

## 4. 总体架构

```
┌───────────────────────────── :app ─────────────────────────────┐
│  UI (Compose)                                                  │
│   LibraryScreen · AddScreen · ReaderScreen · SettingsSheet      │
│        │ ViewModel + StateFlow（单向数据流）                    │
│  Repository                                                    │
│   PoemRepository（书架读写、搜索）                              │
│        │                                                       │
│  Data                                                          │
│   Room (Poem)   ·   AssetLoader(语料)   ·   AnnotationCache     │
└────────────────────────────┬──────────────────────────────────┘
                             │ 调用（纯 JVM，可单测）
┌────────────────────────────▼────────── :engine ────────────────┐
│  ToneDictionary（诗韵新编：韵部 + 平仄）                          │
│  PingZeEngine（逐字标平仄）              RhymeEngine（标句末韵脚）│
└───────────────────────────────────────────────────────────────┘
```

### 4.1 模块职责

- **`:engine`**（纯 Kotlin）：加载字典 → 对给定诗行逐字标注平仄 → 判定韵脚及韵部。输出结构化 `AnnotatedPoem`。所有格律算法在此，单元测试覆盖重点。
- **`:app`**：UI、状态管理、Room、assets 解析、导航。调用 `:engine` 产出标注，缓存到 Room，避免每次进入阅读页重算。

### 4.2 数据流（新增一首诗）

```
AddScreen 搜索结果 ─► PoemRepository.save(poem)
                        │ 调用 AnnotationEngine.annotate(poem)
                        │ 产出 AnnotatedPoem
                        ▼
                   Room: poem + annotation_json 持久化
                        ▼
        LibraryScreen 列表 ← ReaderScreen 读缓存渲染
```

## 5. 数据模型

```kotlin
// :engine —— 核心领域模型
enum class ToneClass { LEVEL, OBLIQUE }        // 平 / 仄

data class CharMeta(
    val char: Char,
    val tone: ToneClass,                       // 按诗韵新编
    val rhyme: String?,                        // 诗韵新编韵部，如 "七齐"
    val isRhymeWord: Boolean,                  // 是否为句末字（韵脚）
    val ambiguous: Boolean,                    // 多音字取判是否存疑
)

data class AnnotatedLine(val text: String, val chars: List<CharMeta>)

data class AnnotatedPoem(
    val poemId: Long,
    val lines: List<AnnotatedLine>,
    val form: PoemForm,                        // 五绝/七绝/五律/七律/古体/词
    val annotations: List<Annotation>,         // 附加说明（入声、多音、待考）
)
```

### 5.1 Room 表（`:app`）

```
poem(id PK, title, author, dynasty, form, content_text,
     added_at, annotation_json)        -- annotation_json 为 AnnotatedPoem 的序列化缓存
```

- 字典不进 DB：诗韵新编字典（韵部 + 平仄）随包作为只读 assets，启动时解析为内存 `Map<Char, ...>`。

## 6. 标注引擎设计（核心）

### 6.1 平仄标注（按《诗韵新编》）

1. 加载「诗韵新编十八韵 + 入声」字典：`Char → (韵部, 声调类别)`。
2. 逐字查表：
   - 阴平 / 阳平 → **平**；
   - 上声 / 去声 / 入声 → **仄**；
   - 未收录字 → 标记"待考"（UI 显示为灰色问号，不武断）。
3. 多音字处理：优先取常见读音；若某读音能更好吻合近体诗格律（如句末当平），则选该读音，并标记 `ambiguous = true`，阅读页提供候选读音查看。

### 6.2 韵脚标注（按《诗韵新编》）

1. 将诗文按标点切分为"句"（`。！？，`等）。
2. 每个**句末字**直接标注为**韵脚**，并给出其在《诗韵新编》中的韵部（如"九开"）。
3. 不做押韵组归并、平仄校验等额外逻辑；未收录字标注为"待考"。
4. 输出：每个韵脚字 + 所属韵部名，供 UI 渲染。

### 6.3 准确率与测试

- 引擎是**纯函数**：`(诗行, 字典) → AnnotatedLine`，可 JVM 单测。
- 测试集：内置的 **10 首精选诗**，断言逐字平仄、句末韵脚与韵部与标准答案一致。
- 已知局限在文档中如实记录（多音字、生僻字、异体字），不假装全对。

## 7. 视觉风格设计（水墨宣纸）

主题名：**「研墨」**。整体走素雅、克制、有纸墨质感的方向。

### 7.1 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 背景（宣纸） | `#F6F1E3` | 暖米色纸面，浅色主题为主基调 |
| 正文墨色 | `#2A2A2A` | 近墨的黑，不纯黑，显温润 |
| 次级文字 | `#6E6A5E` | 作者、朝代、辅助信息 |
| 平仄标记 | `#8C8678` | 墨灰，避免喧宾夺主 |
| 韵脚强调 | `#B03A2E` | 朱砂红，仅用于韵脚与韵部标签 |
| 卡片/分隔 | `#ECE5D1` | 极淡的茶色，纸张层次 |
| 强调按钮 | `#7A2E1B` | 深赭，印章/落款意象 |

- 深色主题（v1 可选）：以暗灰为底、米字为墨的反色方案，优先级低。

### 7.2 排版记号

- 平 → **〇**（空心圆）；仄 → **●**（实心圆）。传统亦用「— / 丨」，设置中可选切换。
- 韵脚字以朱砂**圈注**，紧邻标注其《诗韵新编》韵部（如 `九开`）。
- 未收录 / 待考字 → 淡灰色 `？`。

### 7.3 字体与字距

- 正文：思源宋体，22–30sp（可调），字距 0.15em。
- 标题：更大字号的宋体加粗（用笔画粗细而非颜色区分层级）。
- 韵律空间：行距 1.6–2.0 倍，为平仄标注留出间隙。

### 7.4 动效（轻量）

- 翻页/切换排版用短促淡入（<300ms），不过度。
- 添加成功：印章式的落款动画（可选）。

## 8. 页面与交互设计

共 3 个主屏 + 1 个设置面板。

### 8.1 书架 LibraryScreen（主页）

- 顶栏：应用名「行箸」+ 右侧「+ 添加」按钮。
- 内容：已收藏诗词列表，卡片式（标题 + 作者·朝代 + 体裁标签）。按添加时间倒序，顶部搜索框可对**书架内**过滤。
- 点击卡片 → ReaderScreen。
- 空状态：引导文案"去诗海中添一首吧" + 按钮跳转添加页。

### 8.2 添加 AddScreen（搜索/新增）

- 顶部搜索框（题目/作者），输入防抖 300ms。
- 结果列表：题目 + 作者·朝代 + 体裁，右侧"加入书架"按钮；已加入的显示"已在书架"。
- 点击结果可预览原文（轻量弹层），确认后加入。
- 搜索源 = 内置语料（见 §3.2）。

### 8.3 阅读页 ReaderScreen（核心）

- 顶栏：返回 ← · 居中诗词标题 · 右侧 [设置]。
- 主体：按当前排版渲染 `AnnotatedPoem`（详见 §8.5 / §8.6）。
- 底部（可收起）：韵脚图例与说明 `Annotation`（入声、多音、待考提示）。
- 设置面板（BottomSheet）：
  - 显示平仄 开/关；显示韵脚 开/关；
  - 平仄记号样式：`〇●` / `平仄`；
  - 正文字号滑块。

### 8.4 导航图

```
LibraryScreen ⇄ AddScreen
      │
      ▼
ReaderScreen ─（设置面板）
```

## 8.5 横排排版（默认）

**目标**：现代阅读习惯，兼顾清晰的格律可视化。

每句诗渲染为两行：

```
       〇 丨 〇 〇 丨 丨 〇          ← 平仄记号行（小号、居中于对应字、墨灰）
       风 急 天 高 猿 啸 哀           ← 原文（大字、宋体）
                                        ↑ 韵脚字“哀”朱砂圈注，行末缀 [九开]
```

- 句首缩进统一；对仗联之间留出 0.5 行距，便于看出对仗关系。
- 韵脚字：朱砂描边圆 + 行末小号韵部标签。
- 长诗（词、古体）：常规纵向滚动。

```
（示意图：横排 · 《登高》杜甫 · 首联）
        〇 丨 丨 〇 〇 丨 〇       〇 丨 〇 〇 丨 〇 〇
        风 急 天 高 猿 啸 哀     渚 清 沙 白 鸟 飞 回
                                        ［九开］        ［八微］
```

### 8.6 竖排排版（已移除）

> 竖排格式不易做好（平仄/韵脚标注与逐字对齐难以两全，且无原生支持、成本高），**已从 v1 中移除**，仅保留横排排版。若后续重新评估，需先行原型验证对齐方案（见 §10 风险 R3）。

## 10. 风险与开放问题

### 风险

- **R1 判读准确率**：多音字、古今音差异、生僻/异体字会导致个别字标错。→ 引擎纯函数 + 内置诗测试集 + UI 明示"待考/存疑"，不掩盖。
- **R2 语料过少**：内置仅 10 首，搜索命中范围有限，初版体验偏"示例"。→ 数据源接口（§3.2）预留扩展，v1 如实标注范围。
- **R3 竖排渲染复杂度**：Compose 无原生竖排，需自定义 Layout + 对齐 + 翻页。→ 竖排已从 v1 移除（见 §8.6）；若后续重启，需先做对齐方案原型。
- **R4 语料范围与版权**：只用公版原文；注释/赏析一律不收。

### 开放问题

- **Q1** 诗词数据源：v1 内置 10 首（离线示例）是否可接受？是否希望更快接入联网诗词库以扩充搜索范围？
- **Q2** 是否需要把标注结果导出 / 分享（图片、文本）？
- **Q3** 深色主题是否必须？（默认浅色宣纸风）
- **Q4** 竖排已移除（见 §8.6），"每列固定字数"设置不再需要。

## 附录 A：平仄/韵脚判定示例

以杜甫《登高》首联「风急天高猿啸哀，渚清沙白鸟飞回」为例（示意，非终稿结果）：

| 字 | 诗韵新编 | 平仄 | 韵脚 |
| --- | --- | --- | --- |
| 风 | 十七庚（阴平） | 平 | |
| 急 | 入声 | 仄 | |
| 天 | 十四寒（阴平） | 平 | |
| 高 | 十三豪（阴平） | 平 | |
| 猿 | 十四寒（阳平） | 平 | |
| 啸 | 十三豪（去声） | 仄 | |
| **哀** | 九开（阴平） | 平 | ✔ 句末字 |
| 渚 | 十四寒（上声） | 仄 | |
| 清 | 十七庚（阴平） | 平 | |
| 沙 | 一麻（阴平） | 平 | |
| 白 | 入声 | 仄 | |
| 鸟 | 十三豪（上声） | 仄 | |
| 飞 | 八微（阴平） | 平 | |
| **回** | 八微（阳平） | 平 | ✔ 句末字 |

→ 句末字「哀」「回」标注为韵脚，分别给出其在《诗韵新编》中的韵部「九开」「八微」，仅逐字标注，不做归并。
